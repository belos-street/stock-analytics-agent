# Multi-Dimensional Code Review（多维度代码审查）

> 一句话：一套「通读意图 → 逐维度扫描 → 证据定级 → 表格输出」的可复用审查流程与检查清单，覆盖**可读性 / 一致性 / 正确性 / 健壮性 / 耦合 / 抽象 / 性能 / 安全** 八个维度。适合人肉 review 或让 LLM 按清单走查，避免"只看风格、漏掉实质"。

---

## 审查流程（先流程，后维度）

0. **范围裁剪**：变更/文件量小（< 300 行）直接全扫；大文件按函数/类为单位逐个扫，并优先被其他文件 import 最多的公共函数与变更文件（git diff）。未提供变更范围时，默认入口层 + 核心领域模型，工具类函数抽样；
1. **推断意图**：先整体通读，回答"作者这次要解决什么问题/改了什么行为"，再对照逐维度扫描——问题判断建立在意图之上才不误伤；
2. **测试加权**：先扫同目录是否存在 `*.test.*` / `*_spec.*` 且覆盖核心逻辑——若有，可读性 / 抽象维度的意见降权为"建议"（有测试保护的重构更安全），不构成阻断；测试缺失时风格问题也可提及；
3. **逐维度扫描**：按下方检查清单过一遍，只记录**有代码证据**的问题（禁止"可能/也许"式无证据评论）；
4. **交叉验证**：对每条疑似问题二次确认（读完整文件/调用方/文档），排除误报与上下文缺失；
5. **定级输出**：先查红线（见下，命中即阻断），再按严重度表定 P1/P2/P3，输出表格，逐个给可直接执行的建议。

## 红线熔断（命中即阻断，无需继续扫其余维度）

命中以下任意一条，直接输出阻断级结论（最高优先级），并立即给出证据位置：

- `eval` / `exec` / 字符串拼接 SQL 且参数外部可控（注入面）；
- 硬编码密钥 / Token / 连接串（如 `secret\s*=\s*['"][^'"]+['"]`）；
- 捕获异常后静默吞掉（`catch {}` / 失败返回 null / 丢掉错误且无日志、无上抛），出错不可见；
- 循环体内同步阻塞式 I/O（逐条 HTTP / 逐条 DB 查询）且未批处理。

## 语言适配（目标代码非 TS/JS 时）

本清单语言无关，只取"每个维度要证明什么"。遇到其他语言时将示例词映射为同义概念：类型断言（`as`）→ 该语言的强制转换 / 泛型擦除风险；数据库操作 → 对应 ORM（Python 的 SQLAlchemy / Java 的 MyBatis / Go 的 GORM 等）；并发安全 → Python 看 GIL / 线程锁、Go 看 goroutine 泄漏、TS/JS 看事件循环阻塞。

## 严重度定级（沿用本项目约定）

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| **阻断级（红线）** | 命中「红线熔断」任一条：注入面 / 硬编码密钥 / 静默吞错 / 循环内阻塞 I/O | 直接输出阻断结论并给出证据位置，无需继续扫其余维度 |
| **P1 必修** | 正确性 / 安全 / 数据一致性问题，或明确违背项目硬约束（如 Prisma 迁移、Qdrant 维度） | 合入前必须修复 |
| **P2 重要** | 健壮性 / 一致性明显缺口（特定条件才触发），或与既有实测结论矛盾 | 尽快处理 |
| **P3 可选** | 风格、命名、可读性、性能微优化 | 择机处理，可接受"保持现状" |

## 八维度检查清单

### 1. 可读性 Readability（别人 5 分钟能否读懂意图）

- [ ] 命名表达意图（不靠注释救场）；函数/变量名是"它做什么"而非"它怎么存"？
- [ ] 单函数**有效逻辑行数**（不含空行/注释）> 50 行即触发告警，是否一个函数只做一件事？
- [ ] 注释解释"为什么"而非复述"是什么"？
- [ ] 控制流平直（早 return 减少嵌套、无深层 if/else 金字塔）？
- [ ] 魔法数字 / 魔法字符串有命名常量？

### 2. 一致性 Consistency（同类事物全项目一个模样）

- [ ] 命名风格符合项目约定（camelCase / PascalCase / UPPER_SNAKE / is·has·can）？
- [ ] 同类模式统一：错误处理、日志、单例归属层级、返回类型、资源释放方式？
- [ ] **代码与注释/文档声明一致**（代码和注释互相打架即不一致）？
- [ ] 相近逻辑的两份实现防护是否对齐（一处有校验另一处裸奔 = 漂移信号）？

### 3. 正确性 Correctness（行为是否符合预期）

- [ ] 业务行为与文档/需求描述一致（对照 README / 实施清单）？
- [ ] 边界全覆盖：空输入、0/1/大量、首尾元素、全空/全满？
- [ ] 状态流转完整：失败路径、重跑路径、中途中断的后果？
- [ ] 数值 / 时间 / 时区 / 编码处理正确？
- [ ] 并发下共享状态安全（计数器、Map 写入、游标消费）？

### 4. 健壮性 Robustness（压力与异常下不崩、不静默错）

- [ ] 外部输入 / 第三方响应有校验，而非裸 `as` 断言吞掉 undefined？
- [ ] 网络 / IO 有超时与（必要时的）重试？失败是显式报错还是"静默传 undefined / 丢字段"？
- [ ] 资源正确释放（DB 连接、临时文件、测试 mock 恢复）？
- [ ] 校验是否放在系统边界（用户输入 / 第三方响应），内部无冗余防御（过度防护）？

### 5. 耦合 Coupling（依赖方向与重复度）

- [ ] 依赖方向符合分层（入口 → Service → 数据层），存在反向 / 平级互引吗？
- [ ] 同一逻辑是否多处复制（DRY 破裂）？改一处会漏另一处吗（漂移）？
- [ ] 单例 / 资源归属在正确层级（不要某层"顺便"创建他层资源）？
- [ ] 平级模块共享的东西是否抽到公共层？

### 6. 抽象 Abstraction（复用恰到好处）

- [ ] 存在"提取即可复用"的重复吗？——**同一段 > 4 行的逻辑出现 >= 3 次**，强制要求抽象；
- [ ] 同一个"事实"（常量、类型、维度、枚举）是否只定义一份并由各处引用？
- [ ] 抽象是否过度——为一次性需求造通用层 / 引入不必要的可配置项？
- [ ] 接口命名表达契约而非实现细节？

### 7. 性能 Performance（算力 / IO 热点）

- [ ] 有明显热点吗（循环内 HTTP、逐条写库、同步遍历大目录、重复计算）？
- [ ] 批量机会（合并请求 / 批处理 / 一次事务 vs N 次）是否利用？
- [ ] 并发 / 串行参数有**实测依据**吗（不要凭感觉设并发数）？
- [ ] 去重 / 缓存 / 复用（哈希、幂等）是否有收益空间？

### 8. 安全 Security（涉密钥 / 鉴权 / 注入时必查）

- [ ] 密钥 / 连接串 / token 是否硬编码、是否可能进 git？
- [ ] SQL / 命令 / HTML 是否有注入面（含模糊匹配拼接）？
- [ ] 敏感信息是否进日志 / 错误信息？
- [ ] 鉴权中间件 / 权限边界在入口层正确预留？

## 输出模板

| No. | 严重度 | 维度 | 问题 | 建议 | 位置 |
| --- | --- | --- | --- | --- | --- |
| 1 | P2 重要 | 健壮性 | `as number[]` 强断言吞掉 undefined，异常静默传给下游 | 显式 `if (!v) throw` | `src/xxx.ts#L98` |

位置用代码链接（`file:///` + 行号区间），问题必须先有证据再落表。建议栏对可直接修复的问题可附**最小改法代码块**（如 `if (!v) throw`），便于随表执行修复。

## 反模式提醒

- **流于表面**：只讲命名/风格，漏掉正确性与健壮性实质 → 先跑正确性/健壮性两维；
- **无证据评论**："可能有问题 / 建议检查" → 不写；
- **一次评太多**：合并同类项，跨文件重复只给一个代表位置 + 列受影响文件；
- **分不清级别**：P3 的问题不要写成 P1 阻断，P1 的问题不要降级成"建议"；**红线命中不要降级为 P2/P3 讨论**。
