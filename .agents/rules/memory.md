# 决策记录沉淀规则（轻量版）

让 `.agents/memory/decisions.md` 由 LLM 在对话中**自动维护**，任何 harness（Trae、Codex、WorkBuddy 等）读到本项目都能获取历史决策。

> 💡 与本机 memory 的分工：仓库内 `decisions.md` 存**项目级技术/流程决策**（跨工具可见）；用户偏好与会话级教训走各 harness 自己的记忆系统。

## 一、承接任务前：先读

涉及既有约定的任务（目录归属、工具链选型、命名/架构约定、优先级排序、口径规范等）开始前，先阅读 `.agents/memory/decisions.md`，**避免推翻既有结论或重复讨论**。

## 二、达成决策时：主动追加

当对话中**敲定**了具有长期约束力的决策时（如：选用/弃用某工具或库、目录/文件归属、命名或架构约定、是否迁移、优先级调整等），须在该决策确定后**主动追加**到 `decisions.md`，无需等用户提醒。

### 不需要记录的情况（避免噪音）

- 一次性实现细节、临时调试结论；
- 已存在且未变化的决策；
- 无长期复用价值的单次指令。

## 三、记录格式（严格遵守）

1. **只追加、不覆盖**：在文件末尾新增，编号取当前最大值 +1（如 D7、D8…）。
2. 沿用既有格式：

   ```markdown
   ## Dn · 决策标题

   - **结论**：……
   - **理由**：……
   - **日期**：YYYY-MM-DD
   ```

3. **告知用户**：写入后在回复中简要说明新增了哪条决策（编号 + 标题），便于用户核对或纠正。
